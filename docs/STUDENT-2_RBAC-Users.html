نقاط قوتك — تعرفها إجبارياً: 1) RBAC بأدوار three: admin/manager/employee · 2) role_required على الخادم لا الواجهة · 3) حذف محمي (لا نفسك، لا صاحب مبيعات) · 4) سياسة كلمة مرور تُفرض عند الإنشاء وإعادة التعيين · 5) كل كلمة مرور scrypt لا نص صريح أبداً · 6) كل عملية مسجلة · 7) 12 اختباراً RBAC تثبت الزخارف.

4) العرض الحي أمام الدكتور

  1. .admin ← إنشاء مستخدم manager → نجاح + USER_CREATED في التدقيق.
  2. دخول employee ← فتح /users → 403.
  3. من employee ← تعديل منتج → 403.
  4. عد لأدمن ← إعادة تعيين كلمة مرور لمستخدم → PASSWORD_RESET + كسر القفل.

5) أسئلة المناقشة المتوقعة

س1: اشرح RBAC.
three أدوار: admin (المستخدمون + التدقيق + الكل) · manager (منتجات/عملاء/مخزون/مبيعات) · employee (قراءة منتجات + مبيعاته فقط). يُفرض بديكور على الخادم.
س2: ماذا لو فتح موظف /users في الرابط؟
403 فوراً — الديكور يفحص قبل التنفيذ في الخادم، لا اعتماد على الواجهة. users.py:14.
س3: كيف تضمن تغطية الزخرفة لكل مسار؟
12 اختباراً في test_rbac تسجل بثلاث أدوار وتفحص 200/403 — أي نسيان يظهر فوراً.
س4: سياسة كلمة المرور؟
10–128 حرفاً + كبير + صغير + رقم + رمز في security.py:40-44، تُفرض عند الإنشاء users.py:40-45 وإعادة التعيين :95-100.
س5: إعادة التعيين وكسر القفل؟
admin فقط، يستبدل التجزئة + يصفّر failed_attempts + يحذف locked_until → عودة صاحب الحساب. users.py:102-105.
س6: لماذا لا يحذف المدير نفسه؟
لمنع ترك النظام بلا مدير فعلي. حماية تفويضية قبل التنفيذ: users.py:70-72.
س7: حماية حذف مستخدم له مبيعات؟
IntegrityError من Foreign Key → rollback + رسالة واضحة. users.py:73-79.
س8: هل يمكن أن يتخطى الموظف صلاحيات التعديل؟
لا — التفرقة ليست في الواجهة بل في الخادم: القراءة مفتوحة للكل، لكن الكتابة محصورة في admin/manager عبر role_required الذي يفحص الدور قبل أي تنفيذ. حتى لو غيّر الموظف HTML لا يتغير قرار الخادم.
س9: CRUD للمنتجات كاملاً؟
إنشاء :26-47، قراءة+بحث :11-24، تعديل :49-69، حذف :71-80 — مع تعقيم وتدقيق.
س10: خطوات إنشاء مستخدم آمنة؟
فحص النموذج ← بريد فريد ← سياسة كلمة مرور ← hash_password (scrypt) ← USER_CREATED. users.py:33-58.

6) افتتاحيتك (30 ثانية)

نطاقي هو من يدخل النظام وماذا يجوز له: RBAC بثلاثة أدوار تُفرض بالخادم عبر زخرفة role_required على كل مسار. إدارة المستخدمين آمنة: إنشاء بتجزئة scrypt وبريد فريد، حذف محمي لا يمس النفس ولا أصحاب المبيعات، وإعادة تعيين تكسر القفل — مع CRUD كامل للمنتجات وسياسة كلمة مرور صارمة وتدقيق لكل عملية.
